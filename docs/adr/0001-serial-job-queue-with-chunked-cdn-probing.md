# Serial job queue with chunked range requests, multi-CDN failover, and non-blocking pause/resume

BiliFetch executes Download Jobs one at a time in a persistent background queue rather than running multiple video downloads concurrently. Within the active Download Job, video and audio DASH streams download in parallel using 16 threads of 4 MiB HTTP Range chunks over a 64-connection keep-alive pool (`HTTPAdapter(pool_connections=32, pool_maxsize=64)`), with system proxy environment variables ignored by default (`trust_env=False`). Before downloading, BiliFetch probes candidate Bilibili CDN mirrors (`upos-sz-*`) in parallel to rank mirrors by transfer speed; if any 4 MiB chunk stalls or resets mid-flight, retries immediately rotate across the ranked mirror list while resuming from the byte offset already written. When the user pauses a job or the entire queue, the UI transitions to `pause` state immediately (0ms), the worker pool aborts without waiting for slow socket drains (`shutdown(wait=False, cancel_futures=True)`), and `.part` / `.part.state` files remain on disk so clicking Resume continues immediately in a fresh worker thread.
